# DSH启动器 · 使用说明

DSH启动器是装在 DeepSeek Harness（DSH）里的**通用游戏启动器**。它自己不含任何游戏，需要先把游戏「添加」进来，然后就能像普通启动器一样安装版本、建实例、启动。

两种用法完全等价，可以混着用：

- **对话**：直接跟 DSH 说「添加一个游戏」「装最新版并启动」；
- **面板**：点左下角 **启动游戏**，在图形界面里点选。

---

## 1. 打开面板

左下角侧栏底部的 **启动游戏**（英文界面为 **Launch**）按钮 → 弹出全屏面板。按 `Esc` 或点右上角 × 关闭。

面板分三步走：**先添加/选择游戏 → 点进游戏详情 → 下载版本、建实例、启动**。另外游戏详情里还能管理该游戏的实例与内容，其他游戏同理。

| 页签 | 用途 |
| --- | --- |
| **游戏** | 游戏卡片列表（游戏名、来源、支持的能力、实例数、运行中数）。点任意卡片进入该游戏详情 |
| **添加游戏** | 用内置提供者添加新游戏（GitHub Release / URL 清单 / 手动导入），可先「测试连接」 |
| **设置** | 数据目录、下载并发、重试次数 |

点开某个游戏后的**游戏详情**（同一面板内，左上角 ← 返回）：

- **版本区**：选版本 →「下载并安装」展开安装表单（实例名、该游戏的可选项、可顺带勾选内容）；
- **实例区**：这个游戏的实例列表——启动/停止、日志、打开游戏目录、打开内容目录、删除；
- **内容区**：游戏支持内容时，选一个实例后搜索/安装/删除扩展内容。

面板打开时每 1.5 秒同步一次状态，安装/启动进度实时刷新。在详情里按 `Esc` 会先返回游戏列表，再按一次才关闭面板。

## 2. 添加游戏

添加游戏有三条途径。**添加一次后，这个游戏会一直保存在 `dataRoot/games/*.json`**，以后点进该游戏即可下载版本、新建实例。

### 2.1 GitHub Release（最常用）

准备：仓库名（`owner/name`）、资源文件名特征、主程序名。

对话示例：

```text
你：帮我添加 GitHub 上 owner/name 这个游戏，下载 release 里以 windows-x64.zip 结尾的资源，主程序是 game.exe
DSH：好，我先加进去。
     → launcher_add_game { provider: "github", config: { repo: "owner/name", assetPattern: "windows-x64\\.zip$", executable: "game.exe" } }
     → launcher_list_versions { game: "owner-name" }
```

面板：添加游戏 → 提供者选 **GitHub Release** → 填仓库/资源规则/主程序 → 测试连接 → 保存。

### 2.2 URL 清单

适合自己有下载服务器或第三方提供版本 JSON 的游戏。给一个 `jsonUrl`，返回：

```json
{
  "versions": [
    { "id": "1.2.0", "label": "1.2.0", "url": "https://example.com/game-1.2.0.zip", "sha1": "…", "size": 12345 }
  ],
  "executable": "game.exe",
  "args": ["--data", "."]
}
```

也支持在配置里直接写 `versions` 数组，不依赖外部 JSON。字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 版本号（安装时传它） |
| `url` | 是 | 版本压缩包直链（zip） |
| `sha1` / `size` | 否 | 校验；有则校验，无则跳过 |
| `executable` | 是 | 解压后主程序相对路径 |
| `args` | 否 | 启动参数数组，支持 `{gameDir}` 等占位符 |
| `headers` | 否 | 下载请求头对象（鉴权用） |

### 2.3 手动导入已安装的游戏

已在硬盘上装好、只想用 DSH 面板管理启动：给目录和可执行文件即可。

```text
你：把 D:\Games\SomeGame 加进来，主程序 SomeGame.exe
DSH：→ launcher_add_game { provider: "manual", label: "SomeGame", config: { path: "D:\\Games\\SomeGame", executable: "SomeGame.exe" } }
```

手动导入的游戏「安装」时不会下载任何东西，直接创建实例并链接到该目录。

### 2.4 外部适配器（可选）

安装第三方适配器包后，它注册的游戏会自动出现在游戏列表（来源标记为外部），可按相同方式安装/启动；**数秒内自动生效，无需重启 DSH**（核心与适配器通过 `~/.dsh-launcher/bridge.json` + `<dataRoot>/adapters/` 文件桥接，核心轮询热加载）。适配器开发见 [适配器契约](GAME-ADAPTER.md)。

## 3. 在游戏详情里下载版本并安装

1. 「游戏」页点开游戏 → 进入游戏详情；
2. **版本区**选版本（可点「刷新」强制拉取最新版本清单）；
3. 点 **下载并安装** 展开表单：填实例名；若游戏声明了实例选项（例如内存、加载器、语言），会动态显示；
4. 若游戏支持内容，可在表单里搜索并勾选要一并安装的内容；
5. 确认 → 顶部任务进度显示阶段、百分比、日志；
6. 安装完成后实例出现在 **实例区**，状态变为就绪，可点 **启动**。

对话示例：

```text
你：装这个游戏的最新版本，实例名「我的游戏」
DSH：→ launcher_list_versions → launcher_install_game { game, version: "<版本号>", name: "我的游戏", waitSeconds: 300 }
     （安装是后台任务，返回 jobId；等待结束后返回成功或失败原因）
```

注意：**版本号必须用 `launcher_list_versions` 返回的字符串**，不要自己猜。

## 4. 启动、停止、看日志

- **启动**：游戏详情 → 实例区「启动」；对话 `launcher_launch_game { instance }`。启动是后台任务，启动后 1.5 秒内若进程异常退出会立即报错并附日志尾部。
- **停止**：实例区「停止」；对话 `launcher_stop_game`。会连同子进程树一起结束。
- **日志**：实例区「日志」；对话 `launcher_instance_log`。日志文件在实例目录 `logs/` 下。
- **打开目录**：实例区「游戏目录」「内容目录」；对话 `launcher_open_folder { instance, kind: "game" | "content" | "logs" }`。

## 5. 内容（模组/扩展/DLC）

只有游戏适配器声明了内容能力，游戏详情里才显示内容区。

1. 进入游戏详情 → 内容区选一个该游戏的实例；
2. 输入关键词搜索 → 选择一个项目 → 勾选版本文件（可自动选兼容版本）→ 添加；
3. 已安装列表可逐条确认删除。

对话：

```text
你：给「我的游戏」加一个内容，搜 xxx
DSH：→ launcher_search_content → launcher_content_versions → launcher_add_content
```

内容文件默认放在实例目录的内容文件夹里（由适配器决定），实例区「内容目录」可直达。

## 6. 设置

| 项 | 说明 |
| --- | --- |
| 数据目录 | 只读展示；要改请改 `cordis.patch.yml` 的 `dataRoot` 后重启 |
| 下载并发 | 1–32，默认 16；网络好可上调，被限流则下调 |
| 重试次数 | 0–10，默认 3 |

对话里用 `launcher_set_config { downloadConcurrency: 24, retries: 5 }` 同样生效。

## 7. 实例管理

- **校验**：`launcher_verify_instance` 检查目录、记录、适配器自检（缺文件会列出 problems）；
- **重命名**：`launcher_rename_instance`（对话）；面板实例区提供启动/停止/日志/打开目录/删除；
- **删除**：`launcher_delete_instance { instance, confirm: true }`（连同实例目录一起删，谨慎）；
- 每个实例有独立游戏目录，多版本/多整合互不影响。

## 9. 数据与备份

```text
<dataRoot>/
  instances/<id>/        实例（游戏目录、logs、内容）
  games/*.json           添加过的游戏定义（可备份/迁移）
  adapters/*.mjs         外部适配器
  cache/                 版本清单/下载缓存/运行时缓存（可删，删后重新下载）
  config.json            面板/对话修改的配置
```

迁移到新机器：拷贝整个 `dataRoot` 与插件目录；游戏定义里的绝对路径（手动导入类）需按新路径修改。

## 10. 常见问题

- **面板没有入口 / 工具不存在**：替换插件版本后需要完全退出 DSH 再启动（Host 模块缓存）。
- **添加游戏 403/429**：GitHub API 匿名限流，等几分钟再试。
- **安装卡在下载**：查看任务日志；被镜像限流时降低下载并发，或为游戏配置多个候选 URL。
- **启动即退出**：`launcher_job_status` / `launcher_instance_log` 看具体报错；常见是可执行路径不对（`executable` 相对路径）或缺少运行时。
- **运行时缺失**：支持运行时的游戏可用对话 `launcher_list_runtimes` 查看，安装时自动检测。
- **删除内容后游戏起不来**：确认删的是内容文件而不是游戏本体文件；可用校验功能排查。

## 11. 卸载

1. `plugin_manager` 移除 `@local/dsh-launcher`；
2. 删除插件目录下的 `data/`（或在 patch 里配置的 `dataRoot`）。

外部适配器包单独卸载。
